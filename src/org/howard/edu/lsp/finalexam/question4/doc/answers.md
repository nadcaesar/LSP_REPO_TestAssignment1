# Question 4 — AI Reflection

At the start of this semester I thought of AI tools mainly as a shortcut because it is something that I would use to look up syntax faster or get to a faster solution. That view changed as I actually used AI while working through assignments and I found that the most useful thing AI did was not write code for me, but explain *why* something works a certain way. For example, while debugging the ETL pipeline or figuring out how synchronized methods interact, I would ask AI to walk me through the logic step by step and it helped me build a mental model rather than just copy a solution. Additionally, I noticed that AI can be confidently wrong about edge cases, which forced me to verify everything against the actual Java documentation or by running the code myself which made me more careful about trusting any single source.

Going forward, I plan on using AI as a first-pass explainer and a sounding board for design decisions and not as a replacement for understanding the material. Specifically, when I encounter an unfamiliar concept like the Template Method pattern, I will use AI to gain my bearings and then verify the details by reading the official documentation and or come up with my own test cases. I want to be more intentional about the prompts I write where they are specific, concise and have a lot more context and hopefully with time, the prompts get better explanations than vague ones and I am able to utilise this skill to to communicate more effectively with a code team.
